Ansible Patterns for AWS Instance Management

From IRC discussion about managing AWS instances with Ansible:

Problem: Register a variable in one task and add to it in another task, specifically for creating AWS instances and then cleaning them all up.

Solutions:

1. Simple concatenation in cleanup loop:
   with_items: '{{ machines_created_by_task1 + machines_created_by_task2 + ... }}'

   - Works when task types are stable
   - Must remember to update cleanup loop when adding new task types

2. Use set_fact to build a list:
   set_fact: "{{ instances|default([]).append(registered_var) }}"

   - Add this after creating each instance
   - Builds a cumulative list

3. Use custom tags (recommended for AWS):
   - Tag instances with custom identifiers when creating them
   - Query by tag for cleanup
   - More robust if playbook aborts - can still find and clean up instances
   - Doesn't require maintaining state within the playbook

4. List of dicts with loop (cleanest approach):
   - Define instance configurations as a list of dicts in inventory
   - Single instance creation task with a loop + register
   - Separates configuration from playbook logic
   - Easy to add new OS/Arch combinations without touching playbook

Example structure:
   instances:
     - os: ubuntu
       arch: x86_64
       ami: ami-xxxxx
     - os: amazonlinux
       arch: arm64
       ami: ami-yyyyy


Managing Dynamic Inventory

For creating instances and then doing stuff on them in same playbook:

1. Use ec2 inventory plugin
2. After creating instances on localhost, refresh inventory:
   - ansible.builtin.meta refresh_inventory
   - Or: ansible.builtin.add_host

This allows newly created instances to be immediately available for configuration tasks.
